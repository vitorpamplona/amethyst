# block/buzz upstream review: what Amethyst/Quartz must change to stay interoperable

- **Baseline:** `4ef23609b` (2026-09-29), the last reconciled sync in Quartz's `buzz/README.md`.
- **New head:** `b624eb0f2` (2026-11-18). That is 809 commits.
- **Upstream:** <https://github.com/block/buzz>.
- **Method:** I read the commit log, the diffs of `crates/buzz-core`, `crates/buzz-sdk/src/builders.rs`, the relay handlers (`ingest.rs`, `side_effects.rs`, `command_executor.rs`), `NOSTR.md` and `docs/nips/*`, and the per-commit PR descriptions. I checked each finding against our code by grep and by reading it.
- **Confidence labels:** "confirmed (code)" means I traced both sides in source. "Inferred" means I reasoned from docs or partial reads and did not reproduce it. Nothing was run against a live relay.

## Context change worth knowing first

- **The desktop client left this repo.** Buzz's desktop client now lives in `block/buzz-app` (README `ff030e1af`; a desktop banner in `1fc6a71ef`). This repo keeps the relay, the SDK, the CLI and the Flutter **mobile** client.
  - `desktop/src/features/**` here is now legacy and stops being a good guide to what Buzz's main client renders.
  - Our README's advice to read `desktop/src/features` should point to `block/buzz-app` (not cloned; unverified) and to `mobile/lib`.
  - Several PRs say buzz-app now uses the HTTP `/buzz/v1` read-state API, not NIP-RS.
- **Most of the relay changes are server-internal.** Large share of the 809 commits: Postgres partitioning, trigger retirement, the mesh, push-gateway, user and community deletion, loadgen, App Attest. None of these change the wire.

## Not relevant (no interop impact for us)

- **Database and storage internals:** Postgres partitioning, trigger and FK retirement, replica fences, write-lock and `AdmittedTx` refactors, pool tuning.
- **Infrastructure:** mesh and cross-node fan-out, Redis, loadgen, Helm charts, CI, Hermit, release tooling, App Attest, push-gateway.
- **Account lifecycle:** user, community and agent deletion pipelines, storage accounting, usage metrics, access logs, feature flags.
- **`buzz-acp` / `buzz-agent` harness changes:** observer frame batching and byte bounds, steering, Codex/Claude/Goose adapters, User-Agent strings. The 24200 and 44200 wire formats are unchanged; `kind.rs` has no change to them.
- **Pairing internals:** pairing code-entry (`DesktopCode` / `CodeSubmit` inside the encrypted 24134 payload). We only mark the dialect off 24134 and never pair.
- **Invites:** invite mint and revoke, video previews. The claim route `/api/invites/claim` is unchanged.
- **CLI and SDK ergonomics:** report builder (same NIP-56 shape), status expiry (`30315` + NIP-40 `expiration`), mention pubkey validation, CLI output formats.
- **Search:** profile and message search tuning (`search_sort:"newest"` on HTTP `/query`, prefix search threshold).
- **Engrams (NIP-AE):** an encoder refactor plus a non-normative "entry metadata" convention. The wire is unchanged.
- **Reverted:** `a09b84d23` "agents cannot write in DMs except with their owner" was reverted in `69742376a`.
- **Never shipped:** `kind:44300` "instructions versions" (`acf1ede20`) was superseded by the NIP-AR config artifacts and is not in `kind.rs`.
- **Client UI changes:** mobile and legacy desktop UI and performance work.
